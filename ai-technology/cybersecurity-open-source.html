Cybersecurity & Open Source

Practical security for individuals and small teams, plus how open source licensing and projects work and how to depend on them safely.

By Plert Ankush

Overview

Most security incidents for small teams and individuals come from ordinary causes: reused passwords, unpatched software, leaked keys and convincing phishing messages. Good security is mostly consistent habits, not exotic tools.

Open source sits underneath almost everything you use. Knowing how licences differ, how to judge whether a project is maintained and how to keep dependencies updated is now a basic part of building anything on the web.

What this section covers

  • Passwords, passphrases and password managers: what actually helps
  • Two-factor authentication and the weak points of each method
  • Spotting phishing and social-engineering attempts
  • Keeping secrets such as API keys out of code and screenshots
  • Open source licences explained: permissive vs copyleft
  • Choosing and updating open source dependencies safely

Core concepts

Entropy

A measure of how unpredictable a password is. Length usually matters more than clever substitutions.

Least privilege

Giving an account or key only the access it needs, so a leak does limited damage.

Permissive vs copyleft

Permissive licences allow broad reuse with few conditions. Copyleft licences require derivative work to stay open under similar terms.

Supply-chain risk

The risk that a library you depend on, or one of its dependencies, is compromised or abandoned.

Where to start

Do three things this week: move your important accounts to unique passwords from a manager, turn on two-factor authentication for email, and check that no keys or tokens sit in public repositories or screenshots.
