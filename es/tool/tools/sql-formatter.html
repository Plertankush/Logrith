Preguntas frecuentes

¿Qué palabras clave SQL reconoce?

Las palabras clave comunes como SELECT, FROM, WHERE, JOIN, GROUP BY, ORDER BY, HAVING, INSERT INTO, UPDATE y DELETE FROM se reconocen y se colocan en líneas nuevas con formato en mayúsculas.

¿Esto funciona para todos los dialectos SQL?

Este formateador maneja la sintaxis SQL estándar común a MySQL, PostgreSQL, SQLite y SQL Server. Es posible que la sintaxis muy específica de un dialecto no se formatee a la perfección.

¿El formato modificará el comportamiento de mi consulta?

No, el formato solo agrega espacios en blanco y saltos de línea para facilitar la lectura; no cambia la lógica ni el comportamiento de la consulta.

Cómo usar el formateador SQL

  1. Pega tu SQL

    Sustituya la consulta de ejemplo en el cuadro de entrada por su propia instrucción SQL, por muy desordenada o sin sangría que esté.

  2. Haga clic en Formato SQL

    La herramienta analiza tu consulta en busca de palabras clave reconocidas y la reconstruye colocando cada cláusula en una línea independiente.

  3. Revise la salida formateada.

    Marque la casilla de salida de solo lectura: las palabras clave se convierten a mayúsculas y se colocan en líneas nuevas, mientras que los identificadores y los valores permanecen intactos.

  4. Copia el resultado

    Haz clic en el botón Copiar para obtener el código SQL formateado y pegarlo en tu editor, documentación o solicitud de extracción.

Formateador y embellecedor de SQL

Esta herramienta reformatea las consultas SQL, transformando una consulta densa de una sola línea en una estructura limpia y legible, con cada cláusula principal en su propia línea y un uso coherente de mayúsculas para las palabras clave.

¿Por qué formatear las consultas SQL?

Las consultas SQL copiadas de los registros, generadas por ORM o escritas rápidamente durante la depuración suelen comprimirse en una sola línea, lo que dificulta su lectura a simple vista. Un formato adecuado —colocar cada cláusula principal (SELECT, FROM, WHERE, JOIN, GROUP BY, ORDER BY) en una línea independiente con una indentación uniforme— deja clara la estructura y la lógica de la consulta de inmediato, lo que agiliza la depuración, la revisión del código y la comprensión de las consultas escritas por otros.

Qué hace esta herramienta

El formateador identifica las palabras clave SQL más comunes en tu consulta y las coloca al inicio de una nueva línea, poniéndolas en mayúscula para mayor coherencia, sin modificar el resto de la consulta (nombres de tablas, columnas, valores y condiciones). Esto genera una consulta mucho más fácil de leer y comprender, sin alterar su lógica ni su comportamiento.

Usos comunes

  • Depuración : comprender rápidamente una consulta compleja extraída de los registros de la aplicación.
  • Revisión de código : hacer que el código SQL en las solicitudes de extracción sea más fácil de leer para los revisores.
  • Documentación : presentar las consultas de forma clara en la documentación técnica o en los tutoriales.
  • Aprender SQL : ver la estructura de la consulta desglosada cláusula por cláusula.

Privacidad y procesamiento local

Todo el formato se aplica directamente en tu navegador; tus consultas SQL nunca se envían a un servidor.

Cómo funciona la detección de palabras clave

El formateador primero reduce la consulta a una sola línea eliminando los espacios en blanco adicionales y luego recorre una lista de palabras clave de cláusulas reconocidas, comenzando con frases de varias palabras como SELECT DISTINCT, LEFT OUTER JOIN e INSERT INTO, antes que las más cortas como SELECT, FROM y SET. La comprobación de las frases más largas evita que una palabra clave como "JOIN" se encuentre y se divida en medio de "LEFT JOIN" o "INNER JOIN". Cada coincidencia se coloca al inicio de una nueva línea y se reescribe en mayúsculas, de modo que una consulta escrita completamente en minúsculas se muestra con la capitalización estándar y convencional.

Manejo de cláusulas WHERE con AND / OR

Además de las palabras clave de la cláusula principal, el formateador también busca AND y OR dentro de las condiciones y les aplica una sangría de dos espacios debajo de la cláusula WHERE (o HAVING) a la que pertenecen. Esto permite que un filtro con múltiples condiciones —por ejemplo, status = 'active' AND age > 18 AND country = 'US'— se lea como una lista apilada de condiciones en lugar de una línea larga sin saltos, lo que facilita la detección de una condición faltante o mal ubicada.

Para desarrolladores que trabajan con consultas generadas por ORM

Las consultas generadas por ORM (Django, SQLAlchemy, Sequelize, Hibernate, Eloquent y similares) suelen registrarse como una única línea comprimida sin formato alguno, ya que el ORM no tiene motivo para formatear su salida. Copiar y pegar esa consulta registrada en bruto en esta herramienta suele ser la forma más rápida de leer lo que el ORM envió a la base de datos, lo cual resulta especialmente útil cuando se intenta confirmar si una consulta generada incluye las cláusulas JOIN, WHERE o LIMIT esperadas.

Para estudiantes que aprenden SQL

Ver una consulta dividida en sus cláusulas componentes —SELECT, FROM, WHERE, GROUP BY, ORDER BY—, cada una en una línea independiente, facilita enormemente la comprensión de la estructura general de una sentencia SELECT en comparación con leerla como una sola oración continua. Los estudiantes pueden pegar ejemplos de consultas de libros de texto o tutoriales en línea en la herramienta para ver cómo se relaciona cada cláusula con las demás antes de escribir sus propias consultas desde cero.

Formato manual frente a uso de esta herramienta

Formatear manualmente una consulta corta (añadiendo saltos de línea y capitalizando palabras clave) solo lleva un minuto, pero las consultas con varias cláusulas JOIN, condiciones anidadas o subconsultas resultan tediosas y propensas a errores al reformatearlas manualmente, especialmente bajo presión de tiempo al depurar un problema en producción. Ejecutar la consulta con esta herramienta requiere el mismo esfuerzo independientemente de su longitud y nunca introduce errores tipográficos en las palabras clave ni modifica accidentalmente ningún valor durante el reformateo.

Limitaciones a tener en cuenta

El formateador funciona con palabras clave reconocidas y no analiza el código SQL para generar un árbol de sintaxis completo. Por lo tanto, no reformatea el contenido de las subconsultas con sangría adicional con respecto a la consulta principal, ni valida la sintaxis del código SQL. Simplemente busca las palabras clave, independientemente de si la consulta circundante se ejecutaría o no. La sintaxis específica del proveedor (como TOP de T-SQL o DISTINCT ON de PostgreSQL) que no se encuentra en la lista de palabras clave reconocidas se mantiene tal como se escribió.

Utilizarlo junto con la revisión de código

Cuando revisas una solicitud de extracción que involucra SQL puro (un script de migración, una consulta de informes o una instrucción escrita a mano dentro del código de la aplicación), copiarla y pegarla en el formateador antes de leerla detenidamente puede revelar problemas que son fáciles de pasar por alto en una línea de código concisa, como una cláusula WHERE a la que le falta una condición en una rama de un OR, o un JOIN que en realidad es un CROSS JOIN porque se eliminó la condición ON. Reformatear primero y luego leer de arriba abajo, cláusula por cláusula, es un hábito rápido que detecta más problemas que simplemente leer por encima la consulta comprimida original.

Trabajar con múltiples declaraciones

Si el texto introducido contiene más de una instrucción SQL separada por punto y coma, el formateador procesa todo el bloque pegado como un único texto, dividiéndolo por espacios en blanco y palabras clave en lugar de por los límites de las instrucciones. Para obtener un resultado más claro, generalmente es mejor formatear una instrucción a la vez, especialmente cuando las instrucciones utilizan estructuras de cláusulas muy diferentes (por ejemplo, una instrucción SELECT y una UPDATE en el mismo texto).
