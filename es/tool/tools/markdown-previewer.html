Preguntas frecuentes

¿Qué sintaxis de Markdown es compatible?

Encabezados (#, ##, ###), negrita (**texto**), cursiva (*texto*), código en línea (`código`), enlaces ([texto](url)), citas en bloque (> texto), líneas horizontales (---) y listas básicas (* elemento).

¿Puedo copiar el HTML generado?

Sí, haga clic en "Copiar HTML" para copiar el código HTML generado, listo para pegarlo en una página web o correo electrónico.

¿Se trata de una implementación completa de Markdown?

Esto abarca la sintaxis de Markdown más utilizada para una vista previa rápida. Para funciones avanzadas como tablas o listas anidadas, puede ser necesario un editor de Markdown específico.

Cómo usar el visor de Markdown

  1. Borrar o conservar el texto de muestra

    El editor se carga con ejemplos de Markdown para que puedas ver cómo se muestran los encabezados, el texto en negrita y las listas; haz clic en "Borrar" si quieres empezar con un editor en blanco.

  2. Escribe o pega tu Markdown

    Escribe directamente en el editor de la izquierda o pega texto en formato Markdown copiado de un archivo README, una aplicación de notas u otro editor.

  3. Vea la actualización de vista previa en vivo.

    A medida que escribes, el panel de la derecha vuelve a generar el código HTML al instante, para que puedas comprobar que los encabezados, el formato y los enlaces se vean correctamente.

  4. Copia el HTML generado

    Haz clic en "Copiar HTML" para obtener el código HTML generado, listo para pegarlo en una página web, plantilla de correo electrónico o CMS que acepte HTML sin formato.

Vista previa de Markdown en vivo

Esta herramienta te permite escribir en Markdown —una sintaxis de formato de texto ligera— y ver cómo se actualiza el HTML generado en tiempo real mientras escribes, en paralelo. Es útil para redactar archivos README, documentación, publicaciones en foros o cualquier contenido destinado a una plataforma que utilice Markdown.

¿Qué es Markdown?

Markdown es una sintaxis de texto plano sencilla y legible para dar formato a documentos, diseñada para que incluso el texto fuente sin formato siga siendo fácil de leer. En lugar de hacer clic en botones en un editor de texto enriquecido, se escriben símbolos simples —como **text** para negrita o # Heading para un título— y el Markdown se convierte en HTML con el formato adecuado. Es la sintaxis de formato estándar en plataformas como GitHub, muchas herramientas de blogs, Reddit e innumerables sistemas de documentación.

Sintaxis Markdown compatible

  • Encabezados: # H1, ## H2, ### H3
  • Negrita: **bold text**
  • Cursiva: *italic text*
  • Código en línea: `code`
  • Enlaces: [link text](https://example.com)
  • Citas en bloque: > quoted text
  • Regla horizontal: ---
  • Listas simples: líneas que comienzan con *

¿Por qué previsualizar Markdown antes de publicarlo?

La sintaxis de texto plano de Markdown es fácil de escribir, pero no siempre intuitiva de leer en su formato original, especialmente para quienes no están familiarizados con ella. Previsualizar el código Markdown como HTML renderizado antes de publicarlo ayuda a detectar errores de formato, como un asterisco de cierre que falta y deja el texto en cursiva involuntariamente, o un nivel de encabezado que no se ve bien, antes de que el contenido se publique en GitHub, un blog o un sitio de documentación.

Privacidad y procesamiento local

Todo el análisis y la representación de Markdown se realizan directamente en su navegador mediante JavaScript; su contenido nunca se envía a un servidor.

Cómo funciona la vista previa en directo

Cada pulsación de tecla en el editor activa un evento de entrada que vuelve a ejecutar la conversión de Markdown a HTML en todo el texto y reemplaza el contenido del panel de vista previa. El convertidor procesa el texto línea por línea, buscando patrones para encabezados, citas, líneas horizontales y elementos de lista, y envolviendo cada línea en la etiqueta de bloque correspondiente. A continuación, una segunda pasada analiza el resultado combinado en busca de patrones en línea (negrita, cursiva, código en línea y enlaces), de modo que el formato dentro de un párrafo o elemento de lista se conserve incluso después de que el análisis línea por línea ya lo haya envuelto en una etiqueta de bloque.

Cómo escribir un archivo README con Markdown

GitHub, GitLab y la mayoría de los registros de paquetes generan automáticamente el archivo README.md de un repositorio como HTML formateado. Previsualizar tu README aquí antes de confirmarlo te permite verificar que los encabezados de sección, los bloques de código y las listas con viñetas se vean como deseas, sin necesidad de enviar una confirmación y esperar a que GitHub la procese solo para comprobar el formato.

Markdown para documentación y notas

Muchas plataformas de documentación, generadores de sitios estáticos y aplicaciones para tomar notas —incluidas Jekyll, Hugo, Obsidian y la importación de Markdown de Notion— utilizan la misma sintaxis básica. Redactar el contenido aquí primero permite verificar la estructura y el énfasis antes de pegarlo en la plataforma de publicación.

Errores comunes de formato que detecta esta herramienta

  • Falta un espacio después de # en un encabezado, que algunos analizadores ignoran pero otros interpretan como texto literal.
  • Un ** o * sin coincidencia que deja el resto del párrafo inesperadamente en negrita o cursiva.
  • Un elemento de lista que no comienza con el marcador * esperado y, por lo tanto, se muestra como texto sin formato en lugar de una viñeta.
  • Un enlace escrito sin el paréntesis de cierre, que rompe la URL en lugar de producir un enlace clicable.

Markdown frente a un editor de texto enriquecido

Un editor de texto enriquecido aplica formato mediante botones de la barra de herramientas y lo almacena como marcado oculto, lo que dificulta la lectura, la comparación y la gestión de versiones del archivo subyacente en una herramienta como Git. Markdown mantiene el formato visible como símbolos de texto plano, por lo que un archivo sigue siendo legible incluso antes de su renderizado, y los cambios entre dos versiones de un documento se pueden comparar fácilmente línea por línea.

¿Quién utiliza un visor de Markdown?

Los desarrolladores lo usan para revisar los archivos README y los comentarios del código antes de subirlo a un repositorio. Los redactores técnicos lo usan para elaborar la documentación que posteriormente generará un sitio estático. Los blogueros y usuarios de foros dan formato a sus publicaciones en Markdown para plataformas como Reddit, Dev.to o Hashnode y quieren confirmar el resultado antes de publicarlo, ya que muchas de estas plataformas no ofrecen una vista previa en tiempo real.

Limitaciones a tener en cuenta

Esta vista previa abarca la sintaxis básica de Markdown: encabezados, énfasis, enlaces, citas, líneas horizontales, código en línea y listas simples de un solo nivel. No analiza tablas, listas anidadas o numeradas, bloques de código delimitados con resaltado de sintaxis específico del lenguaje ni imágenes. Si su plataforma de destino admite estas funciones avanzadas, pruebe el formato final directamente en dicha plataforma después de definir la estructura básica aquí.

Edición en paralelo frente a cambio de pestañas

Algunas herramientas de Markdown te obligan a hacer clic en una pestaña aparte de "Vista previa" para ver cómo queda el formato, lo que interrumpe el flujo de escritura al perder de vista el texto original. Como esta herramienta muestra el editor y el resultado renderizado simultáneamente, puedes mantener a la vista tanto el Markdown original como su apariencia formateada mientras escribes, lo que facilita detectar un error de formato en el momento preciso, en lugar de tener que buscarlo después de cambiar de vista.
