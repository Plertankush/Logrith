Preguntas frecuentes

¿Qué es la codificación URL?

La codificación URL (codificación porcentual) reemplaza los caracteres ASCII no seguros con un % seguido de su valor hexadecimal. Esto garantiza que los caracteres especiales en las URL no alteren su estructura. Por ejemplo, un espacio se convierte en %20.

¿Cuál es la diferencia entre encodeURI y encodeURIComponent?

`encodeURI` codifica una URL completa y conserva los caracteres estructurales como /, ?, &, #. `encodeURIComponent` codifica un componente de URL (como el valor de un parámetro de consulta) y también codifica estos caracteres estructurales. Utilice `encodeURIComponent` para valores en cadenas de consulta.

¿Cuándo necesito la codificación de URL?

Necesitas codificar las URL cuando pasas la entrada del usuario como parámetros de consulta de la URL, cuando creas solicitudes de API con caracteres especiales en los valores o cuando creas URL de redireccionamiento que contienen cadenas de consulta.

¿Mi texto se envía a un servidor al codificarlo o decodificarlo?

No, tanto la codificación como la decodificación se realizan instantáneamente en tu navegador mediante las funciones integradas de JavaScript. Nada de lo que introduzcas se transmite a ningún sitio.

¿Qué caracteres se codifican?

Cualquier carácter que no pertenezca al pequeño conjunto considerado "seguro" en las URL (letras, dígitos y algunos símbolos como -, _, . y ~) se convierte a su forma codificada en porcentaje, incluidos los espacios, las ampersands, los signos de interrogación y los caracteres que no son ASCII.

¿Puedo decodificar una URL ya codificada para leerla?

Sí, pegue la URL o cadena codificada en el campo de decodificación y convertirá todas las secuencias codificadas en porcentaje de nuevo a sus caracteres originales legibles.

Acerca de la herramienta de codificación/decodificación de URL

El codificador de URL Logrith convierte el texto a un formato seguro para URL mediante codificación porcentual y lo decodifica de nuevo a texto legible. Esto es fundamental cuando se necesita incluir de forma segura caracteres especiales, espacios o texto no ASCII en una URL, cadena de consulta o solicitud de API sin alterar la estructura de la propia URL.

Las URL solo pueden contener de forma segura un conjunto limitado de caracteres: letras, dígitos y algunos símbolos. Todo lo demás, incluidos los espacios, las ampersands, los signos de interrogación y los caracteres acentuados o no latinos, debe convertirse a una representación codificada en porcentaje antes de poder incluirse en una URL sin causar errores o comportamientos inesperados. Este proceso de conversión se denomina codificación URL o codificación en porcentaje, y esta herramienta lo gestiona instantáneamente en ambas direcciones.

Cómo funciona la codificación porcentual

La codificación porcentual reemplaza un carácter no seguro con un signo de porcentaje seguido del valor hexadecimal del carácter. Por ejemplo, un espacio se convierte en %20. Un signo de ampersand (&) se convierte en %26. Una barra inclinada se convierte en %2F. Este esquema de codificación permite representar cualquier carácter, incluso aquellos que no pertenecen al conjunto básico ASCII, utilizando únicamente el conjunto limitado de caracteres cuya seguridad está garantizada dentro de una URL. Cuando un navegador o servidor recibe una URL codificada con porcentaje, decodifica estas secuencias para obtener sus caracteres originales antes de procesar la solicitud.

encodeURI vs. encodeURIComponent: ¿Cuál usar?

JavaScript proporciona dos funciones de codificación relacionadas pero diferentes, y elegir la correcta es importante. `encodeURI` está diseñada para codificar una URL completa; deja intactos caracteres estructurales como `/`, `?`, `&` y `#`, ya que estos caracteres tienen un significado especial en la estructura general de la URL y no deben codificarse si se está codificando una dirección completa. `encodeURIComponent`, por el contrario, está diseñada para codificar un solo componente o valor, como el valor de un parámetro de consulta, y sí codifica esos caracteres estructurales, ya que dentro de un solo valor, un `&` o un `?` literales deben tratarse como datos en lugar de como parte de la estructura de la URL. Como regla general, utilice `encodeURIComponent` cuando codifique un valor que se colocará dentro de una cadena de consulta, y reserve `encodeURI` para codificar una URL completa que ya tenga su estructura definida.

Situaciones comunes que requieren codificación URL

  • Se pasa la entrada del usuario como parámetro de consulta. Si un término de búsqueda contiene espacios o caracteres especiales, debe codificarse antes de agregarlo a una URL como valor de parámetro.
  • Creación de URL de solicitud de API. Muchas API requieren que ciertos valores, como claves de API o términos de búsqueda, se codifiquen correctamente dentro de la URL de la solicitud.
  • Creación de URL de redireccionamiento. Una URL utilizada como destino de redireccionamiento, especialmente una que contiene una cadena de consulta, a menudo necesita ser codificada para evitar que la URL externa interprete erróneamente la URL anidada.
  • Compartir URL con caracteres especiales. Los nombres de dominio internacionales, las rutas de archivo con espacios o las URL que contienen texto en idiomas distintos del inglés a menudo requieren codificación para que se muestren y funcionen correctamente en todas partes.

Decodificación: Lectura de una URL codificada

La decodificación revierte el proceso, convirtiendo las secuencias codificadas en porcentaje de nuevo a sus caracteres originales legibles. Esto resulta útil cuando se ha copiado una URL de la barra de direcciones del navegador o del registro del servidor y está llena de %20 y %2F difíciles de leer a simple vista; al decodificarla, se revela instantáneamente el texto real o los valores de los parámetros que se están pasando, lo que es especialmente útil para depurar por qué un enlace o una llamada a la API no se comporta como se espera.

Privacidad

Toda la codificación y decodificación se realiza localmente en tu navegador mediante las funciones integradas de JavaScript; nada de lo que introduzcas se envía a un servidor ni se almacena. Esto hace que la herramienta sea segura incluso con valores de consulta confidenciales, parámetros de API o tokens que no quieras que pasen por un servicio de terceros.

Un error común: la doble codificación

Un problema frecuente entre los desarrolladores es la doble codificación: codificar accidentalmente una cadena que ya ha sido codificada una vez, lo que convierte los signos de porcentaje de la primera codificación en su propia forma codificada (%25) y produce un resultado ilegible al decodificarse incorrectamente o al pasarse a un sistema que espera una sola codificación. Esto suele ocurrir cuando un valor se codifica tanto en el lado del cliente como en el del servidor, o cuando una URL se construye concatenando un parámetro ya codificado en una cadena que luego se vuelve a codificar por completo. Si una URL decodificada aún contiene secuencias %25 u otros signos de porcentaje ilegibles, la doble codificación suele ser la causa, y la solución es decodificarla dos veces o, mejor aún, rastrear el código y eliminar el paso de codificación redundante.
