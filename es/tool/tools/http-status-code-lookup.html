Preguntas frecuentes

¿Qué significan los diferentes rangos de códigos de estado?

1xx = informativo, 2xx = éxito, 3xx = redirección, 4xx = error del cliente, 5xx = error del servidor.

¿Cuál es el código de error más común?

Los códigos de estado 404 (No encontrado) y 500 (Error interno del servidor) se encuentran entre los más comunes.

¿Cuál es la diferencia entre 401 y 403?

401 (No autorizado) significa que se requiere autenticación o que esta ha fallado. 403 (Prohibido) significa que el servidor entendió la solicitud pero se niega a autorizarla, incluso si el usuario está autenticado.

  2. Introduzca un código o una palabra clave.

  3. Revisa la lista filtrada.

    Vacía el cuadro de búsqueda para ver de nuevo la lista completa de referencias, ordenada desde información general hasta códigos de error del servidor.

Referencia completa de códigos de estado HTTP

Esta herramienta proporciona una referencia consultable de los códigos de estado HTTP estándar: los números de tres dígitos que los servidores devuelven para indicar el resultado de una solicitud. Busque por código o por palabra clave para encontrar una explicación al instante.

Las cinco categorías de códigos de estado

  • 1xx (Informativo) — la solicitud fue recibida y el procesamiento continúa.
  • 2xx (Éxito) : la solicitud fue recibida, comprendida y aceptada correctamente.
  • 3xx (Redirección) : se requiere una acción adicional para completar la solicitud, normalmente siguiendo una URL diferente.
  • 4xx (Error del cliente) : la solicitud contiene una sintaxis incorrecta o no se puede completar debido a algún problema en el lado del cliente.
  • 5xx (Error del servidor) : el servidor no pudo procesar una solicitud aparentemente válida debido a un problema del servidor.

Por qué son importantes los códigos de estado

Los códigos de estado HTTP son la forma en que los servidores comunican el resultado de cada solicitud a los clientes. Los navegadores, las API y las aplicaciones dependen de estos códigos para saber si una solicitud se realizó correctamente, requiere una redirección, no es válida o si se produjo un problema con el servidor. Comprender el significado de cada código es fundamental para depurar aplicaciones web, crear y utilizar API, y diagnosticar problemas detectados por herramientas de monitorización o registros de errores.

Usos comunes de esta referencia

  • Desarrollo de API : elección del código de estado correcto que se debe devolver para diferentes escenarios de respuesta.
  • Depuración : comprender rápidamente qué significa un código de estado desconocido en un registro o pestaña de red.
  • Aprender desarrollo web : familiarizarse con el vocabulario estándar de códigos de estado HTTP.

Privacidad y procesamiento local

Cómo funciona realmente la búsqueda

Cada vez que se pulsa una tecla en el cuadro de búsqueda, se realiza una búsqueda sencilla comparando tres campos para cada código de estado: el código numérico, su nombre corto y su descripción más larga. Así, al escribir "gateway" aparecen tanto el código 502 Bad Gateway como el 504 Gateway Timeout, mientras que al escribir "50" aparecen todos los códigos que empiezan con esos dígitos, así como cualquier código cuya descripción mencione el número 50. Esto facilita la búsqueda: no es necesario recordar el código exacto para encontrar lo que se busca.

Códigos de estado que los desarrolladores consultan con mayor frecuencia

En la práctica, un pequeño grupo de códigos representa la mayoría de las consultas: 200, 201 y 204 para el lado del éxito; 301, 302 y 304 para redirecciones y almacenamiento en caché; 400, 401, 403, 404 y 429 para errores del lado del cliente; y 500, 502, 503 y 504 para fallos del servidor y la puerta de enlace. Conocer la diferencia entre códigos adyacentes —como 401 frente a 403, o 502 frente a 503 frente a 504— suele ser lo que realmente importa al depurar, ya que cada uno implica un lugar diferente donde buscar la causa raíz.

Lectura de códigos de estado en Browser DevTools

Cuando falla una página o una llamada a la API, la pestaña Red de las herramientas para desarrolladores del navegador muestra el código de estado devuelto junto a cada solicitud. Al pegar ese número en esta herramienta, se obtiene una explicación instantánea sin necesidad de consultar la documentación ni recordar la especificación HTTP completa.

Códigos de estado en el diseño de API

Al crear una API, elegir el código de estado adecuado para cada respuesta es fundamental para que la API sea predecible para quienes la consumen. Una solicitud POST que crea un recurso generalmente debería devolver 201 en lugar de un simple 200; una solicitud sintácticamente correcta pero semánticamente inválida suele ser mejor atendida con 422 que con un 400 genérico; y los clientes con limitaciones de velocidad deberían ver 429 en lugar de un 403 vago. Esta referencia es útil para confirmar el significado preciso de un código antes de incorporarlo a la documentación de la API.

El código de la tetera y otras rarezas

No todos los códigos de estado son puramente funcionales: el código 418 (Soy una tetera) surgió como una broma del Día de los Inocentes en el RFC 2324 y, desde entonces, varios frameworks y servicios lo han mantenido vivo de forma informal como un guiño a la historia de internet. Es un buen recordatorio de que el registro de estados HTTP, aunque estandarizado, tiene algunas peculiaridades que conviene conocer si alguna vez te lo encuentras en la práctica.

Diferencia entre 401 y 403

Estos dos códigos se confunden con frecuencia. Un código 401 No autorizado significa que la solicitud carece de credenciales de autenticación válidas; aún no has demostrado tu identidad. Un código 403 Prohibido significa que el servidor te conoce, pero ha determinado que no tienes permiso para acceder a ese recurso específico. Mezclar estos códigos en una respuesta de API puede llevar a error a quien la recibe y provocar que intente la conexión nuevamente con una solución incorrecta, como volver a iniciar sesión cuando el problema real es la falta de permisos.

Diferencia entre los artículos 502, 503 y 504

Estos tres códigos del lado del servidor suelen agruparse, pero significan cosas diferentes. Un 502 Bad Gateway indica que un servidor que actúa como proxy recibió una respuesta no válida de un servidor ascendente. Un 503 Service Unavailable indica que el servidor está temporalmente sobrecargado o fuera de servicio por mantenimiento. Un 504 Gateway Timeout indica que un servidor proxy no recibió una respuesta del servidor ascendente a tiempo. Distinguir estos códigos ayuda a determinar si el problema reside en el servidor de origen, en un tiempo de espera agotado o en una capa de proxy intermedia.
