Preguntas frecuentes

¿Por qué codificar caracteres especiales como entidades HTML?

Caracteres como <, > y & tienen un significado especial en el marcado HTML. Al codificarlos como entidades, se muestran como texto literal en lugar de interpretarse como sintaxis HTML.

¿Qué es XSS y cómo se relaciona esto?

El cross-site scripting (XSS) es una vulnerabilidad de seguridad que se produce al inyectar código HTML/JavaScript malicioso. Codificar el texto proporcionado por el usuario como entidades antes de mostrarlo es una defensa estándar contra este tipo de ataque.

¿Puede esto decodificar entidades con nombre como ©?

Sí, el decodificador maneja tanto entidades numéricas (') como entidades con nombre común (&, ©, ™ y más).

Codificador y decodificador de entidades HTML

Esta herramienta convierte caracteres especiales en sus equivalentes de entidades HTML (codificación) o decodifica las entidades HTML. Es fundamental para mostrar de forma segura texto que contiene caracteres con significado especial en el marcado HTML.

¿Por qué existen las entidades HTML?

Ciertos caracteres —en particular <, > y &— están reservados en HTML porque se utilizan para definir etiquetas y entidades. Si desea mostrar el carácter literal "<" en el texto de una página web en lugar de que se interprete como el inicio de una etiqueta, debe codificarlo como <. Las entidades HTML proporcionan este mecanismo de escape para los caracteres reservados, así como una forma de representar caracteres que podrían no ser fáciles de escribir (como las comillas curvas, las rayas largas o los símbolos de marca registrada).

La codificación como defensa contra XSS

Más allá de una correcta visualización, la codificación es una práctica de seguridad fundamental. Si un sitio web muestra texto enviado por el usuario sin codificarlo previamente, y dicho texto contiene HTML o JavaScript, el navegador lo interpretará y podría ejecutarlo; esta es la base de los ataques de secuencias de comandos entre sitios (XSS). Codificar los caracteres especiales antes de insertar el contenido del usuario en una página es una de las defensas más importantes contra esta vulnerabilidad, ya que garantiza que la entrada del usuario siempre se trate como texto plano, nunca como código ejecutable.

Entidades HTML comunes

  • & se representa como & (ampersand)
  • < se muestra como < (menor que)
  • > se muestra como > (mayor que)
  • " se muestra como " (comillas dobles)
  • ' se representa como ' (comilla simple/apóstrofe)
  •   se muestra como un espacio sin separación
  • © se muestra como © (símbolo de copyright)

Privacidad y procesamiento local

Todo el proceso de codificación y decodificación se realiza directamente en tu navegador; tu texto nunca se envía a un servidor.

Cómo funciona la codificación en esta herramienta

El codificador se centra en los cinco caracteres que realmente importan para una salida HTML segura: &, <, >, " y '. Cada aparición se reemplaza con su entidad numérica o con nombre correspondiente; primero se codifica el símbolo &, de modo que al codificar un carácter como < no se codifique accidentalmente el símbolo & dentro de su propia entidad. Estos cinco caracteres cubren todos los casos en los que el marcado HTML podría malinterpretarse o romperse con texto literal, razón por la cual la mayoría de las bibliotecas de codificación, incluida esta, se centran específicamente en ellos en lugar de convertir todos los caracteres que no son ASCII.

Cómo funciona la decodificación en esta herramienta

La decodificación utiliza el analizador HTML del propio navegador: el texto de la entidad se asigna al elemento innerHTML de un área de texto oculta, y el navegador decodifica cualquier entidad válida —numérica ('), hexadecimal (') o con nombre (©, ™, —)— exactamente como lo haría al renderizar una página web real. Al leer el value resultante del área de texto, se obtiene el texto sin formato. Este enfoque permite que el decodificador admita toda la gama de entidades que reconoce un navegador, no solo una lista corta predefinida.

Entidades numéricas frente a entidades con nombre

Una entidad con nombre como & es más fácil de leer para un humano en el código fuente, mientras que una entidad numérica como & hace referencia a un carácter directamente mediante su código Unicode y funciona incluso en contextos que no reconocen el conjunto completo de entidades con nombre. Ambas formas se decodifican al mismo carácter, y el decodificador de esta herramienta maneja cualquiera de las dos sin necesidad de saber de antemano cuál se utilizó.

Cuando necesite codificar entidades

  • Mostrar fragmentos de código en una página web: mostrar código HTML o JavaScript literal como texto, en lugar de que el navegador intente renderizarlo.
  • Insertar contenido enviado por el usuario en HTML: codificar comentarios, datos de formularios o cualquier texto procedente de una fuente no fiable antes de insertarlo en el código HTML de una página.
  • Escribir valores de atributos entre comillas: escapar un carácter de comilla dentro de un atributo HTML para que no cierre prematuramente la cadena del atributo.
  • Incrustar texto con un signo de ampersand: nombres de empresas, URL con parámetros de consulta o frases como "Tom & Jerry" que de otro modo se interpretarían erróneamente como el inicio de una entidad.

Cuando necesitas decodificar entidades

La decodificación resulta útil cuando se dispone de código HTML sin procesar —copiado del código fuente de una página, exportado desde un CMS o extraído de la respuesta de una API— y se necesita leer o procesar el contenido textual sin que el escape de entidades interfiera. También es habitual al trabajar con fuentes RSS o datos extraídos mediante web scraping, donde el texto suele entregarse ya codificado en entidades.
