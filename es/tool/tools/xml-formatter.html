Preguntas frecuentes

¿Esto confirma que mi XML está bien formado?

Sí, la herramienta comprueba la estructura básica de XML (coincidencia de etiquetas, anidamiento adecuado) utilizando el analizador XML integrado del navegador e informa de errores si el documento no está bien formado.

¿Cuál es la diferencia entre formatear y minimizar?

El formato añade sangría y saltos de línea para facilitar la lectura. La minimización elimina todos los espacios en blanco innecesarios para reducir el tamaño del archivo y permitir su uso en producción.

¿Esto es válido según un esquema (XSD/DTD)?

No, esto solo comprueba que el XML esté bien formado (sintaxis correcta), no que se ajuste a una definición de esquema específica.

Cómo utilizar el formateador XML

  1. Pegue su XML

    Sustituya el contenido de ejemplo del cuadro de entrada por su propio XML: un documento completo, un fragmento o una respuesta de API.

  2. Formatear o minimizar

    Haz clic en "Formato" para darle formato con sangría, o en "Minimizar" para reducirlo a una sola línea compacta.

  3. Compruebe el resultado de la validación.

    El mensaje de estado le indica inmediatamente si el XML está bien formado o si hay algún problema de sintaxis, como una etiqueta sin cerrar.

  4. Copiar la salida

    Utilice el botón Copiar que aparece junto al cuadro de salida para obtener el resultado formateado o minimizado para su proyecto.

Formateador, embellecedor y validador XML

Esta herramienta formatea los documentos XML con la sangría adecuada para facilitar su lectura, valida que el XML esté bien formado y también puede reducir el XML a una sola línea compacta para su uso en producción.

¿Por qué formatear XML?

El XML generado por las API, exportado desde el software o minimizado para producción suele comprimirse en una sola línea o presentar una indentación inconsistente, lo que dificulta seguir su estructura anidada. Un formato adecuado —con cada elemento en su propia línea y una indentación consistente que refleje la anidación del documento— permite comprender la estructura de inmediato, lo que agiliza la depuración, la revisión de las respuestas de la API y la comprensión de los archivos de configuración.

Qué significa "bien formado"

Un documento XML bien formado sigue las reglas básicas de sintaxis de XML: cada etiqueta de apertura tiene una etiqueta de cierre correspondiente (o se cierra automáticamente), las etiquetas están correctamente anidadas sin superponerse y hay un único elemento raíz que contiene todo lo demás. Esta herramienta comprueba la correcta formación del documento mediante el analizador XML integrado del navegador; sin embargo, cabe destacar que "bien formado" es diferente de "válido según un esquema", que comprobaría además que el documento coincide con una estructura específica esperada (definida por un DTD o XSD), algo que esta herramienta no comprueba.

Usos comunes del XML

  • Respuestas y solicitudes de API : muchas API SOAP y sistemas heredados todavía se comunican mediante XML.
  • Archivos de configuración : muchas aplicaciones, herramientas de compilación y marcos de trabajo utilizan XML para la configuración.
  • Intercambio de datos : XML sigue siendo un método común para el intercambio de datos estructurados entre sistemas, especialmente en entornos empresariales y heredados.
  • Los formatos de documentos , como SVG, las fuentes RSS y los documentos Office Open XML, se basan en XML.

Privacidad y procesamiento local

Todo el formateo, la validación y la minificación se realizan directamente en su navegador; su contenido XML nunca se envía a un servidor.

Cómo el formateador reconstruye la sangría

El formateador primero elimina todos los espacios en blanco existentes entre las etiquetas, comprimiendo el documento al máximo, y luego lo reconstruye token por token. Cada etiqueta de apertura aumenta el nivel de sangría de todo lo que contiene, cada etiqueta de cierre lo reduce, y las etiquetas de cierre automático mantienen el nivel actual sin afectar a lo que sigue. Los elementos que contienen solo un texto corto (como Example Book) se mantienen en una sola línea en lugar de dividirse en tres, lo que hace que la salida sea compacta y legible en lugar de innecesariamente extensa.

Cómo funciona la función de minimización

La minimización hace lo contrario: elimina todos los espacios en blanco entre etiquetas, reduciendo el documento a su formato más pequeño que aún sea XML válido. Esto es importante para su uso en producción, ya que las cargas útiles XML enviadas a través de una API o integradas en una compilación suelen facturarse o medirse según su tamaño. Eliminar los espacios en blanco de formato, que solo existen para facilitar la lectura, reduce ese tamaño sin alterar el significado.

¿Qué se considera un error de sintaxis?

  • Etiquetas sin cerrar : una etiqueta de apertura sin una etiqueta de cierre correspondiente, o viceversa.
  • Etiquetas que no coinciden : una etiqueta de cierre que no coincide con la etiqueta abierta más recientemente, como ....
  • Múltiples elementos raíz : XML requiere exactamente un elemento de nivel superior que englobe todo lo demás; dos elementos raíz hermanos invalidan un documento.
  • Caracteres especiales sin escape : caracteres como & o < que aparecen en el contenido del texto sin ser escapados como entidades.

Para desarrolladores que trabajan con API y SOAP

Los sistemas empresariales heredados y las API basadas en SOAP suelen intercambiar datos en formato XML en lugar de JSON. Al depurar una solicitud o respuesta de uno de estos sistemas, pegar aquí la carga útil sin procesar y formatearla permite visualizar de un vistazo la estructura anidada de la carpeta, el encabezado y el cuerpo, lo que resulta mucho más rápido que examinar una larga lista de etiquetas sin sangría.

Validación XML frente a validación de esquema

Es importante aclarar qué verifica esta herramienta: "bien formado" significa que el XML sigue la sintaxis correcta (etiquetas coincidentes, anidamiento adecuado, un único elemento raíz). No significa que el documento sea "válido" en el sentido estricto de cumplir con un esquema DTD o XSD, que además verificaría que elementos, atributos y su orden coincidan con un contrato predefinido. Un documento puede estar perfectamente bien formado y aun así no superar la validación del esquema si, por ejemplo, falta un atributo obligatorio.

XML en formatos de documentos e imágenes

Varios formatos de archivo que no se suelen asociar inmediatamente con XML, en realidad se basan en él: las imágenes SVG, las fuentes RSS y Atom, y los formatos Office Open XML que sustentan los archivos .docx, .xlsx y .pptx modernos son documentos XML con un vocabulario específico de etiquetas. Al abrir uno de estos archivos en un editor de texto, normalmente se muestra una sola línea ilegible; al procesarlo con este formateador, se convierte en una estructura que se puede inspeccionar, lo cual resulta útil para depurar un icono SVG defectuoso o una fuente RSS con formato incorrecto.

Comparación del formato manual con esta herramienta.

Re-indentar manualmente un documento XML extenso —contando niveles de anidamiento y añadiendo espacios a mano— es lento y propenso a errores, especialmente cuando el documento tiene más de unas pocas docenas de líneas. Un solo error de sangría no daña el XML (ya que la sangría no es relevante para el analizador como lo es en YAML), pero sí dificulta la lectura del documento para quien lo abra posteriormente. Al procesarlo con esta herramienta, la sangría de todo el documento se corrige de forma consistente en una sola pasada.

Manejo de atributos y etiquetas de cierre automático

El formateador conserva los atributos de las etiquetas tal como están escritos —como id="1" en — sin reordenarlos ni reformatearlos, ya que el orden de los atributos puede ser importante para algunos usuarios, aunque la especificación XML no requiera un orden específico.
