Ecosistema de software y desarrolladores

Guías sobre las herramientas, formatos y prácticas en las que confían los desarrolladores: API, formatos de datos, rendimiento web, depuración y flujo de trabajo diario.

Por Plert Ankush

Descripción general

La mayor parte del trabajo de desarrollo de software no consiste en escribir nuevos algoritmos. Consiste en transferir datos entre sistemas, leer formatos de otros desarrolladores, averiguar por qué falla algo y mantener un código fuente comprensible. El ecosistema de desarrolladores es el conjunto de formatos, herramientas y convenciones que lo hacen posible.

Este subtema explica los elementos básicos: las diferencias entre JSON y YAML, el significado de un código de estado HTTP, la potencia y el riesgo de las expresiones regulares, y cómo se mide el rendimiento web. El objetivo es la fluidez, para que puedas leer un mensaje de error y saber dónde buscar la solución.

Qué abarca esta sección

  • Formatos de datos en la práctica: JSON, YAML, XML y CSV, y conversión entre ellos.
  • Lectura de códigos de estado HTTP y errores de API
  • Expresiones regulares: cuándo usarlas y cuándo analizarlas en su lugar.
  • Conceptos básicos sobre el rendimiento web: qué ralentiza una página y cómo medirlo.
  • Hashing, codificación y cifrado: tres cosas diferentes
  • Hábitos que hacen que el código sea legible para el próximo desarrollador.

Conceptos básicos

API

Un método definido para que un programa solicite datos o una acción a otro, generalmente a través de HTTP.

Codificación frente a hash frente a cifrado

La codificación modifica la representación y es reversible por cualquier persona. El hashing es unidireccional. El cifrado solo es reversible con una clave.

Solicitud idempotente

Una solicitud que tiene el mismo efecto tanto si se envía una sola vez como si se envía varias veces, lo que hace que los reintentos sean seguros.

deuda técnica

El coste futuro de un atajo tomado hoy. Es aceptable cuando se elige deliberadamente y se le hace un seguimiento.

¿Por dónde empezar?

Elige el formato de datos que manejas con más frecuencia, pega un ejemplo real en un formateador y aprende qué significa cada mensaje de error. Saber interpretar los errores con calma es la habilidad más transferible en el desarrollo de software.
