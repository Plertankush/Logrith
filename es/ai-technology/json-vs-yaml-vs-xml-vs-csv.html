JSON vs YAML vs XML vs CSV: ¿Qué formato de datos debería utilizar?

Por Plert Ankush · Publicado 12 de noviembre de 2026 · Actualizado 12 de noviembre de 2026 · 4 minutos de lectura

Toda aplicación, tarde o temprano, necesita almacenar datos en un archivo o enviarlos a otro sistema. Los cuatro formatos más comunes son JSON, YAML, XML y CSV. Si bien se solapan lo suficiente como para generar debate, cada uno tiene su propia utilidad.

Esta guía los compara uno al lado del otro, señala los errores que provocan fallos reales y finaliza con una forma sencilla de elegir.

Conclusiones clave

  • Utilice JSON para las API y el intercambio de datos entre programas.
  • Utilice YAML para la configuración editada por humanos y tenga cuidado con sus trampas de espacios en blanco y de adivinación de tipos.
  • Utilice XML cuando necesite documentos con contenido mixto, espacios de nombres o esquemas estrictos.
  • Utilice CSV para tablas planas que desee abrir en una hoja de cálculo. No tiene tipos ni anidamiento.

JSON: el formato predeterminado para el intercambio de datos.

JSON (JavaScript Object Notation) representa los datos como objetos (pares clave-valor), matrices, cadenas de texto, números, valores booleanos y valores nulos. Es compacto, fácil de analizar para programas en prácticamente cualquier lenguaje y lo suficientemente estricto como para que los errores de análisis sean fáciles de detectar.

Puntos fuertes: compatibilidad universal, sintaxis breve y predecible, tipos de datos claros.

Desventajas: no admite comentarios ni comas al final del texto, requiere comillas dobles para cada clave y cadena, y los números grandes pueden perder precisión en algunos lenguajes. La edición manual resulta tediosa para archivos grandes.

Cuando un archivo JSON no se analiza correctamente, la causa suele ser una coma faltante, una coma al final del archivo o comillas simples. Péguelo en un formateador de JSON para ver exactamente dónde falla, o pruebe JSON Repair para errores comunes.

YAML: configuración legible

YAML busca facilitar la lectura y escritura para los humanos. Utiliza sangría en lugar de llaves, permite comentarios y admite los mismos tipos de estructuras que JSON. Se usa ampliamente para la configuración, como en el caso de pipelines de CI y definiciones de contenedores.

Puntos fuertes: muy legible, admite comentarios, conciso para configuraciones anidadas.

Debilidades:

  • Los espacios en blanco son importantes. Una sangría incorrecta altera el significado o daña el archivo. Use espacios, nunca tabulaciones.
  • Adivinación de tipos. Los valores sin comillas pueden interpretarse como otros tipos. En YAML 1.1, palabras como no o off pueden leerse como booleanos, lo que ha provocado el conocido "problema de Noruega", donde el código de país NO se convierte en falso. Codifique las cadenas ambiguas.
  • Complejidad. Funcionalidades como los anclajes y los archivos multidocumento son potentes, pero fáciles de usar incorrectamente.

¿Necesitas convertir entre ambos formatos? Un convertidor de YAML a JSON te ayuda a comprobar que una configuración significa lo que crees que significa.

XML: estructura para documentos

XML encapsula los datos en etiquetas y atributos con nombre. Es un lenguaje extenso, pero esa extensión permite funcionalidades de las que carecen otros lenguajes: espacios de nombres para evitar conflictos, esquemas que validan la estructura rigurosamente y contenido mixto donde se intercalan texto y marcado, como en los documentos.

Puntos fuertes: validación sólida, herramientas maduras, ideal para datos en formato de documento y todavía común en fuentes de datos, formatos de archivos de oficina e integraciones empresariales o gubernamentales.

Desventajas: es demasiado extenso, más complejo de analizar y más difícil de leer que JSON para datos simples. Un formateador XML facilita la inspección de archivos grandes.

CSV: tablas simples

El formato CSV almacena un registro por línea, con valores separados por comas. Cualquier programa de hoja de cálculo puede abrirlo, lo que lo convierte en el formato de exportación estándar para datos tabulares.

Ventajas: pequeño, universal, perfecto para filas y columnas.

Debilidades: no hay tipos de datos (todo es texto hasta que un programa lo adivina), no hay anidamiento y varias trampas sutiles:

  • Los valores que contengan comas o saltos de línea deben ir entre comillas, y las comillas internas deben duplicarse.
  • Las distintas herramientas utilizan diferentes delimitadores (coma, punto y coma, tabulación) y codificaciones.
  • Las hojas de cálculo pueden reformatear valores silenciosamente, como eliminar los ceros iniciales de los identificadores o convertir los nombres de los genes en fechas.

Si un archivo está desordenado, CSV Cleaner puede solucionar los problemas comunes antes de importarlo.

Una forma sencilla de elegir

  1. ¿Los programas lo intercambiarán? Usa JSON.
  2. ¿Se editará con frecuencia y los comentarios serán útiles? Utilice YAML, con comillas bien marcadas, o JSON si puede prescindir de los comentarios.
  3. ¿Es un documento o debe ajustarse a un esquema formal o a un estándar existente? Utilice XML.
  4. ¿Es una tabla plana destinada a una hoja de cálculo o herramienta de análisis? Utilice CSV.

Si no estás seguro, empieza con JSON. Es compatible con todas partes y la conversión posterior suele ser sencilla.

Errores comunes que se deben evitar

  • No se permiten comentarios en formato JSON. Por lo tanto, utilice el campo "_comment" o cambie a YAML.
  • Utilice YAML para los datos que las máquinas escriben y leen. Prefiera JSON para los archivos generados.
  • Abrir y volver a guardar archivos CSV en una hoja de cálculo, lo que puede provocar cambios en los valores sin previo aviso.
  • Mezclar tabulaciones y espacios en YAML.
  • Elegir XML por costumbre cuando los datos son un objeto simple.

Preguntas frecuentes

¿YAML es un superconjunto de JSON?

Un JSON válido generalmente es un YAML 1.2 válido, por lo que la mayoría de los archivos JSON pueden ser leídos por un analizador YAML. Lo contrario no es cierto, ya que YAML tiene muchas características de las que carece JSON.

¿Por qué JSON es más común que XML en las API web?

Es más ligero, más sencillo de leer y se corresponde directamente con los objetos y matrices utilizados en la mayoría de los lenguajes de programación.

¿Puede un archivo CSV contener datos anidados?

No directamente. Puedes aplanar los datos anidados en columnas o almacenar una cadena JSON en una celda, pero en ese caso JSON suele ser una mejor opción.

¿Qué formato es más rápido?

Depende del analizador y de los datos. Para la mayoría de las aplicaciones, la legibilidad, las herramientas y la corrección son más importantes que la velocidad de análisis en sí.
