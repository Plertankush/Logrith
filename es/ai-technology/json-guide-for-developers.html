JSON para desarrolladores: una guía paso a paso

Por Plert Ankush · Publicado 12 de noviembre de 2026 · Actualizado 12 de noviembre de 2026 · 6 minutos de lectura

JSON es el formato que utilizan la mayoría de las API web, archivos de configuración y exportaciones de datos, y también es el formato que cada vez se les exige más a los modelos de IA. Puedes aprender lo básico en una tarde, pero los mismos pocos errores son la causa de la mayoría de los fallos.

Esta guía se divide en cinco partes breves. Léalas en orden o vaya directamente a la que necesite. Cada parte incluye un enlace a una herramienta gratuita para navegadores, para que pueda probar la idea con sus propios datos mientras lee.

Conclusiones clave

  • JSON solo tiene seis tipos de valores y una sintaxis estricta: comillas dobles, sin comentarios y sin comas al final.
  • La mayoría de los errores de análisis sintáctico provienen de un pequeño grupo de errores, así que aprende a detectarlos.
  • Siempre analice los datos dentro de un bloque try/catch (o equivalente) y nunca confíe en la estructura de los datos que usted no creó.
  • Los registros planos se convierten correctamente a CSV; los datos anidados necesitan aplanarse o deben permanecer como JSON.
  • Cuando un modelo de IA genera JSON, valídalo comparándolo con un esquema en lugar de asumir que es correcto.

Parte 1: Qué es JSON y qué puede contener

JSON significa Notación de Objetos JavaScript. Es un formato de texto plano para datos estructurados, creado a partir de la forma en que JavaScript escribe objetos, pero que ahora utilizan casi todos los lenguajes de programación. Un documento JSON se construye a partir de solo seis tipos de valores:

  • Objeto: pares clave-valor no ordenados entre llaves, como {"name": "Asha"}.
  • Matriz: una lista ordenada entre corchetes, como por ejemplo [1, 2, 3].
  • Cadena: texto entre comillas dobles.
  • Número: entero o decimal, sin signo más inicial ni comillas.
  • Booleano: true o false, en minúsculas.
  • Nulo: null, lo que significa un valor vacío intencionalmente.

Los objetos y las matrices pueden contener otros objetos y matrices a cualquier nivel de profundidad, lo que permite que JSON describa datos del mundo real, como un cliente con varios pedidos, cada uno con varios artículos.

Lo que JSON no puede contener es igualmente importante. No existe un tipo de dato para fechas, por lo que estas se escriben como cadenas de texto, generalmente en formato ISO 8601, como "2026-11-15T10:30:00Z". No hay sintaxis para comentarios, ni para valores indefinidos, ni para funciones, ni para valores especiales como infinito o que no sean números. Si necesita alguna de estas funcionalidades, deberá acordar una convención con quien lea sus datos.

Parte 2: Reglas de sintaxis y errores que invalidan JSON

JSON es más estricto que JavaScript. Un archivo que parece correcto para un humano a menudo no pasa el filtro del analizador. Estos son los errores que causan la mayoría de los errores de "Token inesperado":

ErrorEjemploArreglar
coma final{"a": 1,}Eliminar la última coma
Cotizaciones simples{'a': 1}Utilice comillas dobles para las claves y las cadenas de texto.
clave sin comillas{a: 1}Escriba "a"
Comentario// noteElimínelo o guárdelo en un campo "_comentario".
Falta una coma{"a": 1 "b": 2}Agregue una coma entre pares.
Comilla o salto de línea sin escape en una cadena"say "hi""Escapar como \" y \n

Para encontrar la ubicación exacta, pega el texto en el formateador JSON , que lo valida y muestra la posición del primer error. Si los datos provienen de un registro, un mensaje de chat o un modelo de IA y presentan varios de estos problemas a la vez, la herramienta de reparación JSON puede corregir automáticamente los más comunes.

Hay dos detalles más que suelen causar confusión. Técnicamente, la sintaxis permite claves duplicadas, pero su comportamiento varía entre analizadores, así que evítalas. Además, el formato no tiene límite de tamaño para los números, pero la mayoría de los lenguajes los interpretan como números de coma flotante de 64 bits, por lo que los enteros mayores que 9.007.199.254.740.991 pueden perder precisión en JavaScript. Envía identificadores muy largos como cadenas de texto.

Parte 3: Lectura y escritura de JSON en código

Todos los lenguajes de programación principales cuentan con una biblioteca JSON integrada o estándar. Las dos operaciones necesarias son el análisis sintáctico (de texto a datos) y la serialización (de datos a texto).

JavaScript utiliza JSON.parse(text) y JSON.stringify(value, null, 2), donde los dos últimos argumentos producen una salida legible con sangría de dos espacios. Python utiliza json.loads(text) y json.dumps(value, indent=2), además de json.load y json.dump para archivos.

Buenos hábitos que previenen la mayoría de los errores de producción:

  1. Envuelve el análisis sintáctico en un manejo de errores. Una entrada no válida genera una excepción, y una sola respuesta incorrecta no debería provocar que tu programa falle.
  2. No des por sentado que la forma es correcta. Comprueba que las claves que necesitas existen y tienen el tipo esperado antes de usarlas. El encadenamiento opcional en JavaScript y dict.get() en Python son útiles.
  3. Nunca uses eval para analizar JSON. Puede ejecutar código. Usa el analizador real.
  4. Gestiona las fechas de forma específica. Tras la carga, convierte las cadenas ISO en objetos de fecha y vuelve a convertirlas al guardar. Un convertidor de marcas de tiempo Unix resulta útil cuando la API proporciona números de época.
  5. Formato legible para personas, tamaño reducido para máquinas. La sangría facilita la lectura; al eliminar los espacios en blanco, se reduce el tamaño del archivo.

Al trabajar con API, compruebe también el encabezado Content-Type: application/json y el código de estado HTTP antes de analizarlos. De lo contrario, una página de error que se devuelva en HTML se mostrará como un error de análisis JSON confuso. La tabla de códigos de estado HTTP explica el significado de cada código.

Parte 4: Conversión de JSON a CSV, YAML y viceversa

Con frecuencia, es necesario convertir JSON a otros formatos. El enfoque adecuado depende del formato de destino.

Conversión de JSON a CSV. CSV es una tabla plana, por lo que una matriz de objetos similares se mapea perfectamente: cada objeto se convierte en una fila y cada clave en una columna. Los objetos anidados se pueden aplanar en columnas con notación de puntos, como address.city, y las matrices se mantienen mejor como texto JSON dentro de una celda. El convertidor de JSON a CSV funciona en ambas direcciones y maneja las comillas de comas y saltos de línea. Verifique el resultado en una hoja de cálculo y recuerde que las hojas de cálculo pueden reformatear silenciosamente valores como números largos e identificadores con ceros iniciales.

Conversión de JSON a YAML. YAML expresa las mismas estructuras con sangría y permite comentarios, lo que lo hace popular para la configuración. Dado que la mayoría de los JSON son YAML válidos, la conversión suele ser sin pérdida de información, pero al convertir de nuevo, los tipos pueden cambiar si YAML interpreta erróneamente el valor; por ejemplo, si interpreta no como un valor booleano. Utilice el convertidor de YAML a JSON para confirmar que la configuración sigue teniendo el significado previsto.

¿No sabes qué formato se adapta mejor a tu proyecto? La comparación entre JSON, YAML, XML y CSV te ofrece una regla sencilla para elegir.

Parte 5: JSON y modelos de IA

Muchas aplicaciones ahora solicitan a un modelo de lenguaje que devuelva JSON para que otro código pueda utilizar la respuesta: una lista de campos extraídos, una clasificación o un conjunto de etiquetas. Esto funciona bien, pero solo si se trata la salida como una entrada no confiable.

Los modelos pueden generar JSON casi correcto: envuelto en texto adicional o un delimitador de código Markdown, con una coma al final, un campo faltante o un valor del tipo incorrecto. Las API más recientes ofrecen un modo de salida estructurada que restringe el modelo a un esquema proporcionado, lo que reduce considerablemente estos fallos. Aun así, es recomendable crear una red de seguridad:

  1. Solicita únicamente JSON. Indica las claves y los tipos exactos que esperas e incluye un breve ejemplo.
  2. Elimine los contenedores. Elimine las vallas de código y cualquier texto que se encuentre antes de la primera llave y después de la última antes de analizar.
  3. Analizar en un bloque try/catch y, en caso de fallo, volver a intentarlo una vez con el mensaje de error o recurrir a una solución segura.
  4. Validar según un esquema. Comprobar las claves, los tipos y los valores permitidos mediante un validador como JSON Schema, en lugar de confiar en el modelo.
  5. Ten en cuenta la longitud. Las salidas largas pueden cortarse a la mitad al alcanzar el límite de salida del modelo, lo que genera JSON no válido. Mantén las salidas cortas o solicítalas por partes. La calculadora de contexto de IA te ayuda a estimar cuánto texto cabe.

Si una respuesta presenta errores menores, la herramienta de reparación JSON muestra cómo se vería la solución. Sin embargo, en producción, es preferible la prevención (esquemas y validación) a la reparación, ya que los datos reparados silenciosamente pueden ocultar problemas reales. Para comprender por qué los modelos cometen estos errores de formato, consulte cómo funcionan los modelos de lenguaje a gran escala .

Lista de verificación rápida

  • Comillas dobles por todas partes, sin comas al final, sin comentarios.
  • Los identificadores largos se envían como cadenas de texto.
  • Fechas en formato ISO 8601 o como marcas de tiempo explícitas.
  • Análisis sintáctico envuelto en manejo de errores, con comprobaciones de forma posteriores.
  • Se revisaron las exportaciones CSV para detectar la pérdida de ceros iniciales y la presencia de delimitadores incorrectos.
  • JSON generado por IA y validado según un esquema antes de su uso.

Preguntas frecuentes

¿JSON es lo mismo que un objeto JavaScript?

No. JSON es un formato de texto con reglas más estrictas: las claves y las cadenas deben usar comillas dobles, y no se permiten comentarios, funciones ni valores indefinidos. Un objeto JavaScript es un valor en memoria que se convierte a texto JSON y viceversa.

¿Por qué JSON no permite comentarios?

El formato se mantuvo deliberadamente minimalista para que se analice de la misma manera en todas partes. Si necesita comentarios, utilice YAML, un formato como JSON5 (siempre que ambas partes lo admitan) o la clave reservada "_comment".

¿Cómo puedo almacenar una fecha en JSON?

Como una cadena en formato ISO 8601, por ejemplo "2026-11-15T10:30:00Z", o como un número de marca de tiempo Unix. Elija una convención, documéntela y analícela explícitamente después de la carga.

¿Cuál es la diferencia entre JSON y JSON Lines?

JSON Lines (NDJSON) almacena un objeto JSON completo por línea. Es fácil de procesar y añadir datos, lo que lo hace común para registros y grandes conjuntos de datos, pero un archivo completo no constituye un único documento JSON válido.

¿Puedo confiar en el JSON escrito por un modelo de IA?

Trátalo como cualquier dato de entrada no confiable. Si tu proveedor ofrece una función de salida estructurada, analízala de forma segura y valida el resultado con respecto a un esquema antes de que tu código dependa de él.
