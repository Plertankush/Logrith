Hashing vs. Cifrado vs. Codificación: La diferencia explicada

Por el equipo Logrith · Publicado 12 de noviembre de 2026 · Actualizado 12 de noviembre de 2026 · 3 minutos de lectura

Tanto desarrolladores como usuarios comunes suelen confundir el hashing, el cifrado y la codificación. Si bien todos transforman los datos en algo de apariencia diferente, resuelven problemas distintos, y usar el método incorrecto es un error clásico de seguridad. Almacenar contraseñas con Base64, por ejemplo, no ofrece ninguna protección.

Esta guía ofrece una definición clara de cada concepto, una tabla comparativa y reglas prácticas sobre cuándo utilizar cada uno.

Conclusiones clave

  • La codificación cambia el formato de los datos para que los sistemas puedan procesarlos. Cualquiera puede revertirla y no proporciona ninguna confidencialidad.
  • El hashing produce una huella digital de tamaño fijo que no se puede revertir. Se utiliza para comprobaciones de integridad y, con los algoritmos adecuados, para contraseñas.
  • El cifrado oculta los datos y solo se puede revertir con la clave correcta.
  • Nunca guardes contraseñas con codificación simple, cifrado que puedas descifrar o funciones hash rápidas de uso general.

Codificación: cambio de formato

La codificación convierte los datos de una representación a otra para que puedan transmitirse de forma segura a través de un sistema que espera un formato determinado. Base64 transforma los datos binarios en caracteres de texto plano para que puedan insertarse en JSON o en un correo electrónico. La codificación URL reemplaza los caracteres no seguros de una dirección web con códigos de porcentaje.

No hay ningún secreto. Si puedes ver texto en Base64, puedes decodificarlo al instante. Pruébalo tú mismo con la herramienta Base64 o el codificador de URL . Considera la codificación como un empaquetado, nunca como una protección.

Hashing: una huella digital unidireccional

Una función hash toma cualquier entrada y produce una salida de longitud fija, llamada hash o resumen. La misma entrada siempre produce la misma salida; un pequeño cambio en la entrada produce una salida completamente diferente, y no se puede reconstruir el hash para obtener los datos originales.

Entre los usos comunes se incluyen:

  • Verificaciones de integridad. Publica el hash SHA-256 de una descarga para que los usuarios puedan verificar que el archivo no ha sido alterado.
  • Eliminación de duplicados. Los archivos idénticos producen hashes idénticos.
  • Firmas digitales y estructuras de datos. Los hashes se encuentran integrados en muchos sistemas de seguridad.

No todas las funciones hash son igual de seguras. MD5 y SHA-1 presentan vulnerabilidades de colisión conocidas y no deberían utilizarse con fines de seguridad, mientras que la familia SHA-2, como SHA-256, sigue siendo ampliamente utilizada. Puede generar y comparar resúmenes con el Generador de Hash .

El hash de contraseñas es un caso especial.

Los sitios web nunca deberían almacenar tu contraseña. Almacenan un hash y lo comparan con el hash de lo que escribas al iniciar sesión. Sin embargo, un hash simple y rápido como SHA-256 no es la herramienta adecuada, ya que los atacantes pueden probar miles de millones de intentos por segundo contra hashes robados.

El almacenamiento de contraseñas debe utilizar un algoritmo deliberadamente lento diseñado para esta tarea, como Argon2 , bcrypt o scrypt , con un valor aleatorio único para cada contraseña. Este valor garantiza que dos usuarios con la misma contraseña obtengan hashes diferentes y evita el uso de tablas de búsqueda precalculadas. En lugar de programarlo usted mismo, utilice una biblioteca con buenas reseñas.

Cifrado: secreto con una clave

El cifrado codifica los datos de manera que solo alguien con la clave correcta pueda leerlos. Existen dos familias:

  • El cifrado simétrico (por ejemplo, AES) utiliza la misma clave para cifrar y descifrar. Es rápido y se utiliza para archivos, discos y la mayoría de los datos en tránsito una vez establecida la conexión.
  • El cifrado asimétrico (por ejemplo, RSA o sistemas de curva elíptica) utiliza una clave pública para cifrar y una clave privada para descifrar. Resuelve el problema de compartir claves y es la base de los certificados y firmas HTTPS.

La seguridad del cifrado reside en mantener la clave en secreto y en utilizar un algoritmo moderno y probado. Inventar un sistema propio casi siempre es un error.

Una herramienta relacionada: HMAC y tokens firmados

A veces es necesario demostrar que los datos provienen de alguien que conoce un secreto y que no han sido modificados. Un HMAC combina una función hash con una clave secreta para generar dicha prueba. Es el método que utilizan muchas API para firmar webhooks y para firmar tokens web JSON. Puedes inspeccionar las partes legibles de un token con el decodificador JWT , teniendo en cuenta que el contenido de un token está codificado, no cifrado, a menos que se trate específicamente de un token cifrado.

Reglas prácticas

  1. ¿Necesitas que los datos viajen en un formato diferente? Codifica .
  2. ¿Necesitas verificar que los datos no hayan cambiado o almacenar contraseñas? Utiliza hash , usando SHA-256 para la integridad y un algoritmo de hash de contraseñas.
  3. ¿Necesitas mantener tus datos en secreto pero legibles posteriormente? Encripta tus datos con un algoritmo moderno y claves cuidadosamente protegidas.
  4. No utilice la codificación como medida de seguridad, ni utilice funciones hash rápidas para las contraseñas.

Preguntas frecuentes

¿Es Base64 cifrado?

No. Base64 es un sistema de codificación. Cualquiera puede decodificarlo sin una clave, por lo que no ofrece confidencialidad.

¿Se puede invertir un hash?

Aunque no sea matemáticamente preciso, las contraseñas débiles o comunes pueden detectarse mediante el método de adivinación y comprobación, razón por la cual se necesitan funciones hash y sales lentas.

¿Por qué se considera que MD5 está roto?

Los investigadores pueden generar dos entradas diferentes con el mismo hash MD5, lo que se denomina colisión, por lo que no se puede confiar en este método cuando existe preocupación por la manipulación.

¿Cuál es la diferencia entre un hash y una suma de verificación?

Una suma de verificación detecta errores accidentales y suele ser sencilla. Un hash criptográfico también está diseñado para resistir manipulaciones deliberadas.
