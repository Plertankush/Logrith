Technical SEO Checklist for Small Websites

By Plert Ankush · Published Nov 12, 2026 · Updated Nov 12, 2026 · 5 min read

Great content cannot rank if search engines cannot find, read and understand it. Technical SEO is the set of fixes that make your site easy to crawl and index. For a small site the list is short, most items are one-time jobs and getting them right removes a surprising number of silent problems.

This checklist walks through the essentials in the order we would check them, with the reasons behind each item and the mistakes that cause the most damage.

Key takeaways

  • Make sure important pages can be crawled and are not accidentally blocked or set to noindex.
  • Give every page a self-referencing canonical tag and a unique title and description.
  • When URLs change, use permanent (301) redirects and update internal links and sitemaps.
  • Use Search Console to submit sitemaps, inspect URLs and watch for errors.

1. Let search engines crawl your site

  • Check robots.txt. It lives at /robots.txt and tells crawlers what they may fetch. A stray Disallow: / blocks the whole site. A sensible small-site file allows everything and points to your sitemap.
  • Look for accidental noindex. A <meta name="robots" content="noindex"> tag, or an X-Robots-Tag header, keeps a page out of results. These are often left over from development.
  • Use HTTPS everywhere and redirect HTTP to HTTPS.
  • Make navigation crawlable. Use real links (<a href>) so crawlers can discover pages. Important pages should be reachable within a few clicks from the home page.

2. Publish an XML sitemap

A sitemap lists the URLs you want indexed. It does not guarantee indexing, but it helps search engines discover pages and notice updates.

  • Include only canonical, indexable URLs that return a 200 status.
  • Keep lastmod dates accurate and update them only when a page genuinely changes.
  • Reference the sitemap in robots.txt and submit it in Google Search Console.
  • For larger sites, split it into several sitemaps listed in a sitemap index.

3. Set canonical tags

The same page can be reachable under several URLs: with and without a trailing slash, with tracking parameters or on different protocols. A canonical tag tells search engines which one is the preferred version so that ranking signals are not split.

  • Add <link rel="canonical" href="https://example.com/page"> to every page, pointing to its own preferred URL.
  • Use absolute URLs and keep them consistent with your sitemap and internal links.
  • Never point the canonical of an important page at a different page by mistake. Search engines treat the tag as a strong hint.

When we moved Logrith's tools under a new folder, every page's canonical, Open Graph URL, structured data and sitemap entry had to change to the new address. A small script that compares each page's canonical tag with the URL it is served from catches mistakes like this before they ship.

4. Redirect moved pages properly

If you change a URL, send visitors and crawlers from the old address to the new one with a 301 (permanent) redirect. This passes most ranking signals and avoids broken links.

  • Redirect straight to the final page, not through a chain of several redirects.
  • Update internal links to the new URLs rather than relying on redirects forever.
  • Keep the redirects in place long term.
  • Do not redirect everything to the home page. Redirect each old URL to its closest equivalent.

5. Titles, descriptions and headings

  • Give every page a unique <title> that describes it in plain words. Keep it roughly within 60 characters so it is not truncated.
  • Write a unique meta description that summarises the page and invites the click, usually under about 160 characters. It does not directly affect ranking but influences clicks.
  • Use one clear <h1> and logical <h2> and <h3> headings.
  • Use short, readable URLs with words, not IDs. A slug generator helps.

6. Internal links

Links between your own pages help crawlers find content and help readers continue. Link from related articles to each other and to relevant tools or product pages using descriptive anchor text, such as "customer interview questions", not "click here". Fix broken internal links, and avoid orphan pages that nothing links to.

7. Structured data

Structured data, usually JSON-LD, describes your page in a standard vocabulary from schema.org. Useful types for small sites include Article, BreadcrumbList, FAQPage, Organization and WebSite. It helps search engines understand your content and can make you eligible for some rich results, though it never guarantees them.

  • Mark up only what is visible on the page.
  • Validate with the Rich Results Test or the Schema Markup Validator.
  • Keep URLs inside the markup identical to your canonical URLs.

8. Speed and mobile usability

Page experience affects both visitors and rankings. Google's Core Web Vitals describe three measures, with these thresholds for a "good" experience: Largest Contentful Paint within 2.5 seconds, Interaction to Next Paint within 200 milliseconds and Cumulative Layout Shift under 0.1.

  • Compress and correctly size images. An image compressor often gives the biggest quick win.
  • Minify CSS and JavaScript, defer non-essential scripts and avoid loading fonts you do not use.
  • Set width and height on images to prevent layout jumps.
  • Test on a real phone. Most browsing happens there.

The Website Speed Analyzer gives a quick overview, and PageSpeed Insights and Lighthouse give deeper reports.

9. Use Google Search Console

  1. Verify your site (a domain property covers all subdomains and protocols).
  2. Submit your sitemap and check that it reports success.
  3. Use URL Inspection on key pages to see whether they are indexed and to request indexing after major changes.
  4. Review the Pages report for reasons URLs are not indexed, such as "Crawled, currently not indexed", "Duplicate without user-selected canonical" or "Page with redirect".
  5. Check Performance to see which queries and pages earn impressions and clicks, and use it to guide new content.

Indexing takes time, often days or weeks for a new site, and not every page will be indexed. Quality and usefulness of the content strongly influence whether Google chooses to index and show a page.

A 15-minute audit you can run today

  • Open /robots.txt and /sitemap.xml in a browser and confirm they load.
  • View the source of three key pages and check the title, description, canonical and robots tags.
  • Click through your navigation, looking for broken links and redirect chains.
  • Run a speed test on your home page and your slowest page.
  • Open Search Console and read the Pages report.

Frequently asked questions

Do I need an XML sitemap for a small site?

It is not mandatory when pages are well linked, but it is easy, helps discovery and gives you useful reporting in Search Console, so it is recommended.

Should every page have a canonical tag?

Yes. A self-referencing canonical on each indexable page is a common best practice that prevents duplicate-URL issues.

How long does it take for a new page to be indexed?

It can take from a few days to several weeks. Internal links, a sitemap and useful content help, but there is no guaranteed timeline.

Is a meta description a ranking factor?

Not directly, but a clear description can improve click-through from search results.
