Understanding Aspect Ratio Lock

Aspect ratio is the proportional relationship between an image's width and height — for example, a 1920×1080 image has a 16:9 aspect ratio. When aspect ratio lock is enabled, changing the width field automatically recalculates the height to keep that same proportion, and vice versa. This matters because resizing an image to dimensions that don't match its original proportions stretches or squishes the content, distorting faces, logos, and any straight lines in the image. Keeping the lock enabled is almost always the right choice unless you specifically need an image to match an unusual fixed dimension regardless of how it affects the proportions.

Recommended Image Sizes for Common Uses

  • Website hero images — around 1920×1080 pixels, matching standard full-screen display width.
  • Blog post images — around 1200×800 pixels, a good balance of quality and load time for in-article images.
  • Thumbnails — around 300×200 or 400×400 pixels, small enough to load quickly in a grid or list view.
  • Social media sharing images (Open Graph) — 1200×630 pixels, the dimension most platforms expect for link preview images.
  • Profile pictures — typically 400×400 pixels, a square format used across most social and professional platforms.

How Resizing Affects File Size and Quality

Reducing an image's pixel dimensions directly reduces its file size, since there's simply less pixel data to store — a 1920×1080 image resized down to 800×450 will be substantially smaller in file size as a result. Shrinking an image doesn't meaningfully hurt visual quality, since the tool is discarding detail that wouldn't be visible at the smaller size anyway. Enlarging works differently: since there's no additional real detail to draw from, the tool has to interpolate new pixel values to fill in the larger canvas, which can introduce a degree of softness, especially with significant enlargement. For best results, resize down from a high-resolution original rather than resizing up from a small image whenever possible.

Resizing vs. Compressing

These two operations both reduce file size but work differently. Resizing changes the actual pixel dimensions of the image — a 4000×3000 photo resized to 1200×900 has genuinely fewer pixels. Compressing keeps the same pixel dimensions but reduces file size through more efficient encoding, which can introduce some quality loss at higher compression levels. For the largest file size reduction with the least visible quality impact, combining both — resizing to appropriate dimensions, then compressing — usually gives the best result. Privacy

All resizing happens locally in your browser using HTML5 canvas — your image is never uploaded to a server, stored, or logged. This makes the tool safe to use even for personal or sensitive photos you'd rather not send to a third-party service.

A Note on Resizing for Multiple Platforms

If you're preparing the same image for several destinations — say, a website hero image, a social media post, and a thumbnail — it's usually best to start from the highest-resolution original you have and resize down separately for each destination, rather than resizing once and then resizing that smaller result again for a different platform. Resizing down from an already-resized image compounds any quality loss and limits your flexibility if a platform later needs a larger version than what you have on hand. Keeping your original high-resolution file and generating each platform-specific size from it directly gives the sharpest result for every use case, and takes only a few extra seconds compared to repeatedly resizing an already-shrunk copy.
