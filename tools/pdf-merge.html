How PDF Merging Works

This tool uses PDF-Lib, a JavaScript library that works directly with a PDF's internal page structure rather than converting pages to images and stitching them together. When you merge files, each page from every uploaded PDF is copied — complete with its original text, fonts, images, and vector graphics — into a new combined document, in the exact order you've arranged them. Because pages are copied at the structural level rather than rendered and re-encoded, there's no quality loss anywhere in the process.

Why Page Order Matters — and How Reordering Works

When combining multiple source files into one document, the order files were uploaded in isn't always the order you want them to appear. This tool lets you drag any file up or down in the list before merging, which updates the pages' final position in the output PDF. This matters most when assembling something like a report built from several separately-authored sections, where the sections need to read in a specific sequence rather than the order the individual files happened to be created or uploaded.

Common Reasons to Merge PDFs

  • Combining a cover letter with a resume into one file for a job application that requests a single attachment.
  • Assembling a complete report from sections written or exported separately, such as individual chapters or departmental contributions.
  • Merging scanned pages that were captured as separate files into one continuous document.
  • Combining supporting documents — invoices, receipts, contracts — into a single file for easier filing or submission.
  • Creating a single print-ready file from multiple source documents, so printing happens in one pass rather than several.

Merging vs. Appending: Is There a Difference?

In everyday use, "merging" and "appending" PDFs usually mean the same thing — combining the pages of multiple files into one continuous document. The term "appending" sometimes implies strictly adding files to the end of an existing document one at a time, while "merging" more generally describes combining any set of files in any order. This tool supports both: upload all the files you need at once and arrange them exactly how you want, whether that means strictly appending one file after another or freely reordering a larger set of documents.

What Happens to Bookmarks, Metadata, and Links

Page-level content — text, images, vector graphics, and embedded fonts — carries over completely during a merge, since PDF-Lib copies each page's full content stream. Document-level metadata, such as the title or author field, and internal navigation elements like bookmarks are tied to the original file structure and are not automatically combined or renumbered across the merged set. For most use cases, like combining scans, reports, or supporting documents, this has no practical effect since the content itself is what matters; it's only relevant if your original PDFs relied heavily on an internal bookmark outline for navigation.

Privacy and Browser-Based Processing

Every file you upload, and the merge operation itself, stays entirely within your browser — nothing is sent to a server, logged, or stored anywhere outside your own device. This makes the tool a safe option for merging confidential contracts, financial records, or personal documents without that content ever passing through a third party.

Tips for a Smooth Merge

Before merging, it's worth double-checking each source file individually to confirm it has the pages and content you expect, since fixing an issue after merging means re-uploading and starting over. If the final merged document needs specific pages removed afterward, Logrith's PDF Page Remover can clean it up without needing to redo the merge from scratch. For very large combined documents, keep in mind that total output size is roughly the sum of all input file sizes, so if the final file needs to stay under a certain size limit for emailing or uploading, running it through a PDF compressor after merging can help bring it down.

When You Might Need to Merge Instead of Keep Files Separate

It's worth pausing to consider whether merging is actually the right move for a given situation. Some contexts specifically call for a single file — an online application form that only accepts one upload, a printing job that needs to run as one continuous job, or an email where attaching one file is cleaner than several. Other contexts are better served keeping files separate, such as when each document needs to be referenced, edited, or shared independently later. Merging is a one-way convenience: once combined, you'd need to split the file again to separate the original documents, so it's generally worth keeping untouched copies of your original files before merging, just in case you need them individually again later.
