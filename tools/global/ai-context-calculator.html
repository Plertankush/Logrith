What Is a Token in AI Language Models?

A token is the basic unit of text that a language model actually reads and generates. Models don't process raw characters or whole words one at a time — they work with tokens produced by a tokenizer, which breaks text into a sequence of sub-word pieces drawn from a fixed vocabulary learned during training. A common English word like "the" or "is" is often a single token, while a longer or less frequent word, a made-up word, a number, or a piece of code might be split into two, three, or more tokens. Every request you send to an AI model and every response it generates is measured and billed in tokens, not in words or characters, which is why understanding roughly how many tokens your text contains matters before you send it anywhere.

Why Token Count Differs From Word Count

Because tokenizers split on sub-word units rather than whitespace, token count and word count are related but never identical. For typical English prose, a widely cited rule of thumb is that one token corresponds to roughly four characters, or equivalently about three-quarters of a word — so 100 words of English text usually lands somewhere around 130 to 140 tokens. Text that's dense with rare words, technical jargon, non-English characters, code syntax, or unusual punctuation tends to use more tokens per word, because the tokenizer has to fall back to smaller pieces for anything outside its most common vocabulary entries.

Why This Tool Doesn't Pretend to Be an Exact Tokenizer

Precise, model-accurate tokenization requires the real byte-pair-encoding vocabulary file that a specific model was trained with, and different model families use different vocabularies that can change over time. Shipping a fake approximation that silently pretends to be exact would give you a number that looks precise but is actually meaningless. Instead, this tool is upfront about what it does: it applies two well-known, published estimation heuristics — a character-based estimate (roughly 1 token per 4 characters) and a word-based estimate (roughly 1 token per 0.75 words) — and shows both, clearly labeled as approximations. For everyday planning, such as checking whether a prompt is roughly within budget, this level of accuracy is sufficient, and it's honest about its own limits rather than quietly guessing.

What Is a Context Window?

A context window is the maximum number of tokens a model can hold in memory for a single request, counting your input (the prompt, any attached documents, and prior conversation turns) together with the model's own generated output. If the combined token count exceeds the context window, the model either truncates older content, rejects the request, or simply cannot "see" everything you've provided. Context windows vary enormously by model and provider, from a few thousand tokens on smaller or older models up to a million tokens or more on newer, large-context models. Because exact window sizes change frequently as providers release new models, this tool uses generic size tiers — Small, Medium, Large, Extra Large, and Very Large — so the comparison stays useful without going stale.

Why Context Window Usage Matters

If you're building a long conversation, feeding in a large document, or pasting an entire codebase, you need to know whether it will even fit before the model truncates or refuses part of it. Many providers also charge by the token, so a request using a large fraction of the context window is typically more expensive. Some models also perform less reliably when a context window is nearly full, so keeping headroom rather than running right up against the limit is often good practice.

Estimating API Cost

Token-based pricing means the cost of a request scales directly with how many tokens it contains. Rather than hardcoding specific vendor prices into this tool — which would quickly become outdated as providers adjust their pricing — the cost estimator lets you type in whatever rate you currently know, per 1,000 or per 1,000,000 tokens, and instantly multiplies it by the estimated token count of your pasted text. This keeps the calculator useful regardless of which provider or model you're planning to use.

How the Estimate Is Calculated

This tool computes character, word, sentence, and paragraph counts directly from your pasted text, then derives two token estimates — character count divided by four, and word count divided by 0.75 — averaging them into one working estimate used for the context bar and cost calculation. Both heuristic values are shown separately so you can see the spread. Everything runs synchronously in plain JavaScript, with no network request involved.

AI Token & Context Calculator FAQ

Is this an exact token count like tiktoken?
No. Exact tokenization depends on the specific byte-pair-encoding vocabulary of a given model, which isn't something that can be faithfully reproduced client-side without shipping that model's real vocabulary file. This tool uses two well-known, transparent heuristics instead and is clearly labeled as an estimate, not an exact count.
Why does token count differ from word count?
Tokenizers split text into sub-word pieces, not whole words. Common short words are often a single token, while longer or less common words, numbers, punctuation and code can split into multiple tokens. As a result, token count is usually higher than word count for normal English text.
What is a context window?
A context window is the maximum number of tokens a model can process at once across your input and its own output combined. If your text exceeds the context window, the model cannot see all of it, or the request may be rejected outright.
Does this tool upload my text anywhere?
No. All counting and estimation happens locally in your browser using JavaScript. Your text is never sent to Logrith or any other server.
Can I estimate API cost with this tool?
Yes. Enter your own price per 1,000 or per 1,000,000 tokens, since provider pricing changes frequently and varies by model, and the tool multiplies that rate by the estimated token count to show an approximate cost for your input text.
