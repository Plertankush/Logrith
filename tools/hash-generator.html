How the Hashing Actually Works

This tool uses the Web Crypto API's crypto.subtle.digest() method, a native browser function built specifically for cryptographic operations. For text input, the string is first encoded to raw bytes with TextEncoder; for files, the browser reads the file directly into an ArrayBuffer. That byte data is passed to the digest function, which returns a fixed-length binary hash that's then converted to a readable hexadecimal string. Because this is a native browser API rather than a JavaScript-only implementation, hashing runs quickly even on large files without freezing the page.

SHA-1 vs SHA-256 vs SHA-384 vs SHA-512

  • SHA-1 (160-bit): produces a 40-character hex output; retained here for compatibility with older systems and legacy checksums, but collision attacks make it unsuitable for security-sensitive verification today.
  • SHA-256 (256-bit): produces a 64-character hex output; the de facto standard for file checksums, Git commit hashes, TLS certificates, and most modern software integrity checks.
  • SHA-384 (384-bit): produces a 96-character hex output; a truncated variant of SHA-512 used where a stronger hash than SHA-256 is wanted without the full SHA-512 length.
  • SHA-512 (512-bit): produces a 128-character hex output; the longest and most collision-resistant option in this set, often used in high-security contexts or 64-bit optimized systems.

Verifying a File Download

Software publishers frequently list an official SHA-256 checksum next to a download link specifically so users can confirm the file wasn't corrupted in transit or tampered with. After downloading, switch to the Hash File tab, select the downloaded file, and compare the generated SHA-256 value against the one published on the official site using the Compare Hashes tab — an exact match confirms the file is byte-for-byte identical to what the publisher released.

Common Mistakes When Comparing Hashes

  • Comparing hashes from different algorithms: a SHA-1 hash will never equal a SHA-256 hash even for identical input, since they're different-length outputs from different functions — always compare like with like.
  • Trailing whitespace or newlines: hashing text pasted with an extra trailing newline produces a different hash than the same text without it, since hash functions are sensitive to every byte of input.
  • Case sensitivity confusion: hex hash output is case-insensitive in meaning but displayed in lowercase here — the compare tool lowercases both inputs automatically so capitalization differences won't cause a false mismatch.

Frequently Asked Questions

What is a cryptographic hash?

A cryptographic hash is a fixed-size string generated from input data. The same input always creates the same output, but even a tiny change in the original text or file creates a different result.

Which algorithm should I use?

SHA-256 is the most practical option for general use. SHA-384 and SHA-512 produce longer outputs, while SHA-1 is older and no longer recommended for modern security-sensitive use.

Can I verify file integrity with this tool?

Yes. Generate the hash of your downloaded file and compare it with the official checksum provided by the software publisher. If both hashes match exactly, the file is unchanged.

Does this tool upload my file anywhere?

No. The hashing process runs locally in your browser, so your file remains on your device during the operation.
