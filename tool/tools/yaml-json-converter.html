Convert Between YAML and JSON

This tool converts YAML documents to JSON, or JSON to YAML, handling nested objects and arrays. It's useful for developers working with configuration files, Kubernetes manifests, CI/CD pipelines, and APIs that use either format.

YAML vs. JSON

Both YAML and JSON represent the same underlying data structures — objects (key-value mappings) and arrays (ordered lists) — but with different syntax. JSON uses curly braces, square brackets, and quoted keys, making it precise and easy for programs to parse. YAML uses indentation and minimal punctuation instead, which many developers find easier to read and write by hand, especially for configuration files, at the cost of being more sensitive to exact indentation.

Where YAML Is Commonly Used

  • Configuration files — many modern tools (Docker Compose, GitHub Actions, Ansible) use YAML for configuration.
  • Kubernetes manifests — Kubernetes resource definitions are written almost exclusively in YAML.
  • CI/CD pipelines — build and deployment pipeline definitions are frequently written in YAML.
  • Static site generators — front matter in many static site generators uses YAML syntax.

Why Convert Between the Two

Converting between YAML and JSON is useful when an API expects one format but your source data is in the other, when debugging by viewing YAML config in more explicit JSON form, or when migrating a project's configuration format. Since both represent identical underlying data, conversion between them is lossless for standard data types.

How the YAML Parser Handles Structure

This converter reads YAML line by line, using each line's indentation level to figure out where it sits in the overall structure. When indentation increases, the parser treats that as a nested object or list; when it decreases, it closes out the current nesting level and returns to a shallower one. List items are recognized by a leading hyphen, and each key-value pair separated by a colon is interpreted either as a scalar value or the start of a new nested block depending on whether anything follows the colon on the same line.

Which Value Types Are Recognized

  • Booleans — the literal words true and false convert to JSON booleans.
  • Null values — null, ~, or an empty value convert to JSON null.
  • Numbers — unquoted numeric values convert to JSON numbers rather than strings.
  • Quoted strings — values wrapped in single or double quotes have the quotes stripped and are kept as plain strings.
  • Plain strings — anything that isn't a recognized boolean, null, or number is treated as a string.

What Happens When Converting JSON Back to YAML

In the reverse direction, the tool walks the parsed JSON object recursively: nested objects become indented blocks, arrays become hyphen-prefixed lists (with nested objects inside an array getting their own indented block), and scalar values are written as plain text unless they look like they could be misread as a number, boolean, or null — in which case they're quoted to preserve their original type as a string.

For Developers Working with Kubernetes and CI/CD

Kubernetes manifests, GitHub Actions workflows, and Docker Compose files are all written in YAML, but debugging tools, APIs, and many programming language standard libraries work more naturally with JSON. Converting a manifest to JSON temporarily makes it easier to validate structure, diff against an API response, or feed into a JSON Schema validator, then convert back to YAML once you're done.

Limitations to Be Aware Of

This converter supports the YAML features most configuration files actually use: nested mappings, lists, and the standard scalar types. It does not support YAML anchors and aliases (&/* references for reusing blocks), multi-document files separated by ---, or flow-style inline collections like {key: value} written on a single line. If your YAML file relies on these advanced features, a dedicated YAML library will handle them more reliably.

Common Mistakes

  • Mixing tabs and spaces for indentation — YAML (and this parser) relies on consistent spacing, and a stray tab can shift an entire block to the wrong nesting level.
  • Forgetting a trailing comma check in JSON mode — valid JSON never has a trailing comma after the last item in an object or array.
  • Assuming quoted numbers stay as numbers — a YAML value like "30" in quotes is intentionally kept as a string, not converted to the number 30.

Why Indentation Matters More in YAML Than JSON

JSON's structure is defined by its braces and brackets, so whitespace between tokens is purely cosmetic — you can minify a JSON file to a single line and it still parses correctly. YAML has no such delimiters; indentation is the only thing telling the parser where one block ends and another begins. This is why a YAML file that looks almost identical to a working one can fail to parse if a single line is indented with one space instead of two — it's also why converting to JSON is a useful sanity check, since the resulting braces make the actual nesting visible and unambiguous.

Typical Workflow for Config File Debugging

A common pattern among developers is pasting a YAML config that's behaving unexpectedly into this tool, converting it to JSON, and visually comparing the nesting against what was intended. Because JSON's braces make every level of nesting explicit, it's often faster to spot a misplaced key or an array that accidentally became an object than it is by staring at raw YAML indentation.
