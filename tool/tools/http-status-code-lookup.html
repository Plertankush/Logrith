Frequently Asked Questions

What do the different status code ranges mean?

1xx = informational, 2xx = success, 3xx = redirection, 4xx = client error, 5xx = server error.

What's the most common error code?

404 (Not Found) and 500 (Internal Server Error) are among the most commonly encountered status codes.

What's the difference between 401 and 403?

401 (Unauthorized) means authentication is required or has failed. 403 (Forbidden) means the server understood the request but refuses to authorize it, even if authenticated.

Complete HTTP Status Code Reference

This tool provides a searchable reference of standard HTTP status codes — the three-digit numbers servers return to indicate the result of a request. Search by code number or by keyword to instantly find an explanation.

The Five Status Code Categories

  • 1xx (Informational) — the request was received and processing continues.
  • 2xx (Success) — the request was successfully received, understood, and accepted.
  • 3xx (Redirection) — further action is needed to complete the request, typically following a different URL.
  • 4xx (Client Error) — the request contains bad syntax or cannot be fulfilled due to something on the client's side.
  • 5xx (Server Error) — the server failed to fulfill an apparently valid request due to a server-side problem.

Why Status Codes Matter

HTTP status codes are how servers communicate the outcome of every request to clients — browsers, APIs, and applications all rely on these codes to know whether a request succeeded, needs a redirect, was invalid, or hit a server problem. Understanding what each code means is essential for debugging web applications, building and consuming APIs, and diagnosing issues reported by monitoring tools or error logs.

How the Search Actually Works

Every keystroke in the search box runs a simple match against three fields for each status code: the numeric code itself, its short name, and its longer description. So typing "gateway" surfaces both 502 Bad Gateway and 504 Gateway Timeout, while typing "50" surfaces every code that starts with those digits as well as any code whose description happens to mention the number 50. This makes the lookup forgiving — you don't need to remember the exact code number to find what you're looking for.

Status Codes Developers Look Up Most Often

In practice, a small handful of codes account for most lookups: 200, 201, 204 on the success side; 301, 302, 304 for redirects and caching; 400, 401, 403, 404, 429 for client-side errors; and 500, 502, 503, 504 for server and gateway failures. Knowing the difference between adjacent codes — like 401 versus 403, or 502 versus 503 versus 504 — is often what actually matters when debugging, since each implies a different place to look for the root cause.

Reading Status Codes in Browser DevTools

When a page or API call fails, the Network tab in browser developer tools shows the returned status code next to each request. Pasting that number into this lookup gives an instant explanation without needing to search documentation or remember the full HTTP specification.

Status Codes in API Design

When building an API, picking the right status code for each response is part of making the API predictable for whoever consumes it. A POST that creates a resource should typically return 201 rather than a plain 200; a request that's syntactically fine but semantically invalid is often better served by 422 than a generic 400; and rate-limited clients should see 429 rather than a vague 403. This reference is useful for confirming the precise meaning of a code before committing to it in API documentation.

The Teapot Code and Other Oddities

Not every status code is purely functional — 418 I'm a Teapot originated as an April Fools joke in RFC 2324 and has since been kept alive informally by various frameworks and services as a nod to internet history. It's a good reminder that the HTTP status registry, while standardized, has some quirks worth knowing if you ever encounter it in the wild.

Difference Between 401 and 403

These two codes are frequently confused. A 401 Unauthorized means the request lacks valid authentication credentials altogether — you haven't proven who you are yet. A 403 Forbidden means the server knows who you are but has decided you don't have permission to access that specific resource. Mixing these up in an API response can mislead whoever is consuming it into retrying with the wrong fix, such as re-logging in when the real issue is a missing permission.

Difference Between 502, 503, and 504

These three server-side codes often get grouped together but mean different things. A 502 Bad Gateway means a server acting as a proxy got an invalid response from an upstream server. A 503 Service Unavailable means the server is temporarily overloaded or down for maintenance. A 504 Gateway Timeout means a proxy server didn't get a response from the upstream server in time. Telling these apart helps narrow down whether the problem is the origin server, a timeout, or a proxy layer in between.
